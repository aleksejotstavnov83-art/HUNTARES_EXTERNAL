# HUNTARES External — native ESP 2D Box source

Основа: предоставленный исходный архив `bycmd source (1).zip`. Вместо демонстрационных прямоугольников сохранён реальный C++ путь `player registry → player world positions → camera → world_to_screen → 2D box` из исходника.

## Сделано
- Android-лоадер с собственной чёрно-белой темой и предоставленной аватаркой.
- Root-запуск собственного нативного C++ движка в отдельном процессе.
- В игре: круглая кнопка с аватаркой и полупрозрачное старое меню HUNTARES.
- Единственная игровая функция ESP 2D Box; управление толщиной линии.
- Выход из меню и скрытие при отсутствии Standoff 2 на переднем плане.
- Автоматическое завершение процесса после закрытия игры (условное).
- GitHub Actions workflow для сборки APK.

## ВАЖНО: совместимость с Standoff 2 1.1.0 НЕ подтверждена
Исходный bycmd содержит **сигнатуры `libunity.so` версии 1.0.0**, несмотря на название архива и комментарии. `get_lib()` проверяет два ожидаемых значения по фиксированным адресам (см. `engine/src/other/memory.hpp`). Пока не получен соответствующий `libunity.so` для проверки этих сигнатур и игрового запуска, этот код **может вообще не обнаружить движок игры**, а ESP останется пустым. Это не демонстрационные боксы: реальный ESP включается только после удачного чтения игровых сущностей, иначе ничего не рисуется.

**APK не собран и в игре не проверен в этой среде**, потому что отсутствуют Android SDK/NDK и доступ к сети для их установки. GitHub Actions соберёт `app-debug.apk`, но сборка ≠ подтверждение работоспособности ESP.

## Сборка через GitHub
1. Создай репозиторий, распакуй архив целиком в корень, сохраняя `.github/workflows/android.yml`.
2. Открой вкладку **Actions → Build HUNTARES External APK → Run workflow**.
3. Скачай из последнего запуска артефакт `HUNTARES-External-debug` (там `app-debug.apk`).
4. Установи APK на ARM64-устройство и разреши root-доступ.
5. Нажми «ЗАПУСТИТЬ HUNTARES». Лог доступен кнопкой «ПОСМОТРЕТЬ ЛОГ».
6. Если нет ESP: смотри строки `no mapping matches`, `registry`, `camera`, `ESP blocked` и `projected`.

## Что проверять после сборки
- Ошибка `no mapping matches ... 1.0.0` означает несовместимые сигнатуры libunity, а не неисправность отрисовки.
- `ESP blocked at: player discovery / registry scan` — не найдены игровые объекты.
- `ESP blocked at: native / transform camera resolution` — не найдена камера.
- `projected=0` — нет успешной проекции.
- `projected>0` — движок рассчитывает экранные координаты реальных противников; визуально нужно проверить в игре.

## Структура
- `engine/src/func/visuals.cpp`: настоящая логика 2D ESP
- `engine/src/game/`: поиск сущностей, камера и математика
- `engine/src/other/memory.hpp`: процессы и сигнатуры
- `engine/src/ui/bar.cpp`: круглая кнопка с аватаркой
- `engine/src/ui/menu.cpp`: стиль меню
- `app/src/main/java/`: Android-лоадер
- `.github/workflows/android.yml`: автоматическая сборка

Личный проект, используйте исходники с учётом прав на код исходного проекта и правил игры.
